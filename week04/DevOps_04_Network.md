## 1. 네트워크 기초

### 1-1. IP 주소

IP 주소(Internet Protocol Address)는 네트워크에서 장치를 식별하는 주소다.

| 구분 | 설명 |
|---|---|
| **공인 IP** (Public IP) | 인터넷에서 장치를 식별하고 통신할 때 쓰는 공개 주소 |
| **사설 IP** (Private IP) | 가정·회사 같은 내부 네트워크에서 쓰는 주소 |
| **NAT** (Network Address Translation) | 사설 IP와 공인 IP 사이에서 주소를 바꿔주는 기술 |

대표적인 사설 IP 대역:

```text
10.0.0.0    ~ 10.255.255.255
172.16.0.0  ~ 172.31.255.255
192.168.0.0 ~ 192.168.255.255
```

### ☎️ 회사 전화 비유

- **공인 IP** = 회사 **대표번호** (밖에서 거는 번호)
- **사설 IP** = 회사 안 **내선번호** (안에서만 통함)
- **NAT** = 대표번호로 온 전화를 내선으로 연결해 주는 **교환원**

### 1-2. IP 주소와 포트 번호

- **IP 주소**: 통신할 **컴퓨터**를 찾는 주소
- **포트 번호**: 그 컴퓨터 안에서 실행 중인 **서비스**를 구분하는 출입구 (범위 `0 ~ 65535`)

| 포트 | 서비스 |
|---|---|
| 22 | SSH |
| 80 | HTTP |
| 443 | HTTPS |
| 3306 | MySQL |
| 6379 | Redis |
| 5000 | Flask |
| 8080 | 개발용 웹 서버 |

### 🏢 건물 비유

- **IP 주소** = 건물 주소 (어느 건물로 갈지)
- **포트 번호** = 건물 안의 **창구 번호** (22번 창구는 SSH, 80번 창구는 HTTP …)

#### Docker 포트 매핑

```bash
docker run -p 8080:80 nginx
```

| 부분 | 의미 |
|---|---|
| `docker run` | 컨테이너 실행 |
| `-p 8080:80` | `-p 호스트포트:컨테이너포트` 형식의 포트 매핑 |
| `nginx` | 실행할 이미지 |

→ 호스트의 **8080**번 포트로 들어온 요청을 컨테이너의 **80**번 포트로 전달한다.
(건물 8080번 창구로 온 손님을 안쪽 nginx 사무실 80번 창구로 안내하는 것)

### 1-3. TCP와 UDP

| 구분 | TCP | UDP |
|---|---|---|
| 연결 방식 | 연결 지향 | 비연결 지향 |
| 전달 확인 | 제공 | 보장하지 않음 |
| 순서 보장 | 제공 | 보장하지 않음 |
| 특징 | 신뢰성 중시 | 속도·간결성 중시 |

### 📮 우편 비유

- **TCP** = **등기우편**: 받았는지 확인하고, 순서대로 도착하게 관리함
- **UDP** = **전단지 돌리기**: 일단 빠르게 뿌리고, 받았는지·순서는 신경 안 씀

### 1-4. TCP/IP 계층 구조

| 계층 | 역할 | 주요 프로토콜·기술 |
|---|---|---|
| 응용 계층 | 사용자 서비스 제공 | HTTP, DNS, SSH |
| 전송 계층 | 데이터 전달, 포트 관리 | TCP, UDP |
| 인터넷 계층 | IP 주소 기반 경로 설정 | IP |
| 네트워크 액세스 계층 | 실제 네트워크 전송 | Ethernet, Wi-Fi |

### 1-5. localhost와 특수 IP 주소

| 주소 | 의미 |
|---|---|
| `127.0.0.1` | 자기 자신의 컴퓨터를 가리키는 **루프백 주소** |
| `localhost` | 자기 자신의 컴퓨터를 가리키는 **호스트 이름** |
| `0.0.0.0` | 서버가 **모든 IPv4 네트워크 인터페이스**에서 접속을 받도록 바인딩하는 주소 |

> [!WARNING]
> `localhost`는 외부 서버가 아니라 **지금 이 컴퓨터**를 뜻한다.
> `0.0.0.0`은 서버가 **기다릴 때(바인딩)** 쓰는 주소이고, 브라우저로 접속할 목적지 주소로 쓰지 않는다.

### 🏪 가게 비유

- **localhost / 127.0.0.1** = "**나 자신**" (내 컴퓨터가 내 컴퓨터에게 말 걸기)
- **0.0.0.0** = 가게의 **모든 출입문**을 열어두고 손님을 기다림 → 손님은 "모든 출입문"이 아니라 **실제 가게 주소**로 찾아와야 함

## 2. DNS와 서버 탐색

### 2-1. DNS란?

DNS(Domain Name System)는 **도메인 이름을 IP 주소로 변환**하는 시스템이다.
`google.com`을 입력하면 DNS로 그 도메인에 해당하는 IP 주소를 조회한다.

### 📱 연락처 비유

DNS = 휴대폰 **연락처**. "엄마"(도메인)를 누르면 실제 전화번호(IP 주소)로 전화가 걸리는 것과 같다.

### 2-2. 네트워크 정보 확인

```bash
ip addr
```

네트워크 인터페이스와 IP 주소 정보를 확인한다.

```bash
ip addr show eth0
```

`show eth0`: `eth0` 인터페이스 하나만 확인한다.

```bash
hostname -I
```

`-I`: 현재 컴퓨터에 설정된 IP 주소를 출력한다.

```bash
curl ifconfig.me
```

외부(인터넷)에서 보이는 **공인 IP** 주소를 확인한다. (`ifconfig.me`는 요청한 쪽의 IP를 돌려주는 사이트)

macOS에서는:

```bash
ifconfig
```

```bash
ipconfig getifaddr en0
```

`getifaddr en0`: `en0` 인터페이스의 IP 주소만 출력한다.

### 2-3. ping

```bash
ping -c 4 8.8.8.8
```

| 부분 | 의미 |
|---|---|
| `ping` | 대상에 **ICMP** 패킷을 보내 응답이 오는지 확인 |
| `-c 4` | 4번(count) 보내고 종료 (`-c`가 없으면 `Ctrl + C`로 멈출 때까지 계속 보냄) |
| `8.8.8.8` | Google Public DNS의 IP 주소 |

도메인으로도 확인할 수 있다.

```bash
ping -c 4 google.com
```

> [!NOTE]
> ping이 실패했다고 **반드시 서버가 다운된 것은 아니다.**
> 방화벽이나 서버 설정에서 ICMP 요청을 막아둘 수 있다. (초인종을 꺼둔 집 → 대답이 없어도 사람이 없는 건 아님)

### 2-4. DNS 조회

먼저 DNS 조회 도구(`dig`, `nslookup`)를 설치한다.

```bash
sudo apt install -y dnsutils
```

| 부분 | 의미 |
|---|---|
| `sudo` | 관리자 권한으로 실행 |
| `apt install` | 패키지 설치 |
| `-y` | 설치 중 확인 질문에 자동으로 yes |
| `dnsutils` | `dig`, `nslookup`이 들어 있는 패키지 |

```bash
dig google.com
```

```bash
dig google.com +short
```

```bash
nslookup google.com
```

```bash
cat /etc/hosts
```

| 명령어 | 역할 |
|---|---|
| `dig google.com` | 상세 DNS 조회 |
| `dig google.com +short` | `+short`: 결과(IP)만 간단히 출력 |
| `nslookup google.com` | DNS 조회 |
| `cat /etc/hosts` | 로컬 호스트 이름 ↔ IP 매핑 확인 |

## 3. 서버 통신과 응답 확인

### 3-1. curl

URL로 서버에 요청을 보내고 응답을 확인하는 명령어다.

```bash
curl https://example.com
```

서버가 돌려준 응답 **본문**(HTML 등)을 출력한다.

```bash
curl -I https://example.com
```

`-I`: 응답 **헤더**만 확인한다. (상태 코드, Content-Type 등)

```bash
curl -s https://example.com
```

`-s`: silent. 진행 표시 같은 부가 출력을 숨긴다.

```bash
curl -o result.html https://example.com
```

`-o result.html`: 응답 내용을 화면 대신 `result.html` **파일에 저장**한다.

### ✉️ 편지 비유

- `curl` = 편지 **내용(본문)** 읽기
- `curl -I` = 편지 **봉투(헤더)**만 보기 — 보낸 곳, 상태(200 등), 종류(Content-Type)

### 3-2. jq

JSON을 보기 좋게 출력하거나 원하는 값만 꺼내는 도구다.

예시 JSON:

```json
{
  "name": "OpenAI",
  "users": [
    { "name": "Kim" }
  ]
}
```

```bash
echo '{"name":"OpenAI"}' | jq '.'
```

`.`: JSON **전체**를 보기 좋게 출력한다.

```bash
echo '{"name":"OpenAI"}' | jq '.name'
```

`.name`: `name` 필드 값 추출 → `"OpenAI"`

```bash
echo '{"users":[{"name":"Kim"}]}' | jq '.users[0].name'
```

`.users[0].name`: `users` 배열의 **첫 번째(0번)** 요소에서 `name` 추출 → `"Kim"`

```bash
echo '{"name":"OpenAI"}' | jq -r '.name'
```

`-r`: raw output. 문자열의 따옴표를 빼고 출력 → `OpenAI`

| 부분 | 의미 |
|---|---|
| `echo '...'` | JSON 문자열 출력 |
| `\|` | 파이프: 앞 명령의 출력을 `jq`의 입력으로 전달 |
| `.name` | name 필드 |
| `.users[0]` | users 배열의 첫 번째 요소 (번호는 0부터) |
| `-r` | 따옴표 없이 출력 |

### 3-3. HTTP 상태 코드

서버가 요청을 처리한 결과를 숫자로 알려준다.

| 코드 | 의미 | 설명 |
|---|---|---|
| 200 | OK | 요청 성공 |
| 400 | Bad Request | 잘못된 요청 |
| 404 | Not Found | 요청한 리소스를 찾을 수 없음 |
| 500 | Internal Server Error | 서버 내부 오류 |
| 503 | Service Unavailable | 서비스를 일시적으로 이용할 수 없음 |

- **2xx**: 요청 성공
- **4xx**: 클라이언트(요청한 쪽) 오류
- **5xx**: 서버 쪽 오류

### 🍜 식당 비유

- **200** = 주문한 음식 잘 나옴
- **404** = 메뉴판에 없는 메뉴를 주문함 (손님 쪽 문제 → 4xx)
- **500** = 주방에서 사고 남 (가게 쪽 문제 → 5xx)
- **503** = 지금 너무 바빠서 잠시 주문을 못 받음

### 3-4. ss

```bash
ss -tlnp
```

현재 컴퓨터에서 TCP로 연결을 **기다리고 있는(LISTEN)** 포트와 프로세스를 확인한다.

| 옵션 | 의미 |
|---|---|
| `-t` | TCP 소켓 표시 |
| `-l` | LISTEN 상태인 소켓만 표시 |
| `-n` | 주소와 포트를 이름 대신 **숫자**로 표시 |
| `-p` | 관련 프로세스 정보(이름, PID) 표시 |

특정 포트만 확인:

```bash
ss -tlnp | grep 8080
```

`| grep 8080`: 출력 결과에서 `8080`이 들어간 줄만 보여준다.

- **LISTEN**: 서버가 그 포트에서 연결을 기다리는 상태
- **PID**: Process ID, 프로세스 식별 번호

> [!NOTE]
> 다른 사용자(예: root)가 실행한 프로세스 정보는 `-p`로 안 보일 수 있다. 이때는 `sudo ss -tlnp`로 확인한다.

macOS에서는:

```bash
lsof -nP -iTCP -sTCP:LISTEN
```

| 옵션 | 의미 |
|---|---|
| `-n` / `-P` | 주소 / 포트를 숫자로 표시 |
| `-iTCP` | TCP 연결만 |
| `-sTCP:LISTEN` | LISTEN 상태인 것만 |

## 4. 서버 실행과 문제 해결

### 4-1. Python 간단 웹 서버

Python의 `http.server` 모듈을 쓰면 웹 서버 프로그램을 따로 설치하지 않고 테스트용 웹 서버를 띄울 수 있다.

```bash
mkdir -p ~/devops/week04/site
```

| 부분 | 의미 |
|---|---|
| `mkdir` | 디렉터리 생성 |
| `-p` | 중간(상위) 디렉터리가 없으면 함께 생성 |
| `~` | 현재 사용자의 홈 디렉터리 |

```bash
cd ~/devops/week04/site
```

`cd`(Change Directory): 작업 디렉터리를 이동한다.

```bash
cp "/mnt/c/<경로>/index.html" .
```

| 부분 | 의미 |
|---|---|
| `cp` | 파일 복사 |
| `"/mnt/c/<경로>/index.html"` | 원본 파일 (`/mnt/c/` = WSL에서 보이는 윈도우 C 드라이브) |
| `.` | 복사할 위치 = 현재 디렉터리 |

```bash
python3 -m http.server 8080
```

| 부분 | 의미 |
|---|---|
| `python3` | Python 3 실행 |
| `-m` | 모듈을 실행 |
| `http.server` | 간단한 HTTP 서버 모듈 |
| `8080` | 서버가 사용할 포트 번호 |

브라우저에서 접속:

```text
http://localhost:8080
```

정상 실행 시 나오는 메시지 예시:

```text
Serving HTTP on 0.0.0.0 port 8080 (http://0.0.0.0:8080/) ...
```

브라우저에서 페이지를 요청하면 나오는 로그 예시:

```text
"GET / HTTP/1.1" 200 -
```

→ 브라우저가 `/` 경로를 **GET** 방식으로 요청했고, 서버가 **200**(성공)으로 응답했다는 뜻이다.

### 4-2. 0.0.0.0 바인딩

```bash
python3 -m http.server 8080 --bind 0.0.0.0
```

`--bind 0.0.0.0`: 모든 IPv4 네트워크 인터페이스에서 접속을 받도록 서버를 실행한다.

> [!NOTE]
> `http.server`는 `--bind`를 생략해도 기본으로 모든 인터페이스에서 접속을 받는다. (그래서 시작 메시지에 `0.0.0.0`이 보임. 환경에 따라 IPv6 표기인 `::`로 나오기도 함)
> `--bind 0.0.0.0`은 이를 **명시적으로** IPv4 전체로 지정하는 것이다.

- `0.0.0.0`은 서버가 **기다릴** 주소다.
- 외부 컴퓨터는 서버의 **실제 IP 주소와 포트**로 접속해야 한다.
- 외부 접속에는 방화벽과 네트워크 설정도 영향을 준다.

### 4-3. 서버가 잘 떠 있는지 확인

```bash
curl http://localhost:8080
```

서버의 응답 본문 확인

```bash
curl -I http://localhost:8080
```

HTTP 헤더와 상태 코드 확인

```bash
ss -tlnp | grep 8080
```

8080 포트의 LISTEN 상태와 프로세스 확인

### 4-4. 포트 충돌 (Port Conflict)

이미 사용 중인 포트로 새 서버를 실행하면 포트 충돌이 난다.

```text
OSError: [Errno 98] Address already in use
```

→ 같은 IP 주소·프로토콜에서 그 포트를 **이미 다른 프로세스가 쓰고 있다**는 뜻이다.

### 🪑 자리 비유

이미 누가 앉아 있는 자리(포트)에 또 앉으려고 한 것. → **다른 자리에 앉거나**, **앉아 있는 사람을 비켜달라고** 해야 한다.

**해결 방법 ① 다른 포트 사용**

```bash
python3 -m http.server 8000
```

**해결 방법 ② 기존 프로세스 종료**

1) 어떤 프로세스가 8080을 쓰는지 확인

```bash
ss -tlnp | grep 8080
```

출력 예시:

```text
users:(("python3",pid=4299,fd=3))
```

2) PID가 `4299`라면 종료 (내 결과에 나온 PID로 바꿔서 실행)

```bash
kill 4299
```

`kill`은 지정한 PID에 종료 신호를 보낸다. 기본값은 **SIGTERM**(정상 종료 요청)이다.

### 4-5. pkill

```bash
pkill -f "http.server"
```

| 부분 | 의미 |
|---|---|
| `pkill` | 프로세스 **이름이나 패턴**으로 찾아서 종료 신호 보내기 |
| `-f` | 프로세스 이름만이 아니라 **실행 명령어 전체**에서 패턴을 검색 |
| `"http.server"` | 찾을 패턴 |

→ `python3 -m http.server 8080`처럼 명령어 안에 `http.server`가 들어간 프로세스를 찾아 종료한다.

> [!WARNING]
> 패턴에 맞는 프로세스가 여러 개면 **전부 종료**될 수 있다.

| 비교 | `kill` | `pkill` |
|---|---|---|
| 대상 지정 | **PID 번호** | **이름·패턴** |
| 예시 | `kill 4299` | `pkill -f "http.server"` |

### 4-6. 백그라운드 실행

```bash
python3 -m http.server 8080 &
python3 -m http.server 8081 &
python3 -m http.server 8082 &
```

명령어 끝의 `&`는 **백그라운드 실행**이다. 서버가 터미널을 차지하지 않아서 다른 명령어를 계속 입력할 수 있다.

실행 중인 Python 서버 확인:

```bash
ss -tlnp | grep python
```

서버 응답 확인:

```bash
curl -s localhost:8080 | head -3
```

| 부분 | 의미 |
|---|---|
| `curl -s` | 진행 표시 없이 요청 |
| `\|` | 파이프: 앞 명령의 출력을 뒤 명령의 입력으로 |
| `head -3` | 처음 3줄만 출력 |

여러 서버를 한 번에 종료:

```bash
pkill -f "http.server"
```

### 4-7. 방화벽 (Firewall)

네트워크로 들어오고 나가는 통신을 보안 규칙에 따라 **허용하거나 차단**하는 시스템이다.

예시:

| 포트 | 설정 | 의미 |
|---|---|---|
| 22 | 허용 | SSH 접속 허용 |
| 80 | 허용 | HTTP 접속 허용 |
| 443 | 허용 | HTTPS 접속 허용 |
| 8080 | 차단 | 8080 포트 외부 접근 차단 |

> [!IMPORTANT]
> **서버가 LISTEN 상태라고 해서 외부에서 반드시 접속할 수 있는 것은 아니다.**
>
> - `ss -tlnp`: 서버가 그 포트에서 연결을 **기다리는지** 확인
> - 방화벽: 그 포트의 통신을 **허용하는지** 확인

### 🛡️ 건물 경비 비유

- **LISTEN** = 가게가 문 열고 손님을 기다리는 중
- **방화벽** = 건물 입구 **경비원**. 가게가 열려 있어도 경비원이 막으면 손님은 못 들어온다.

### 전체 흐름

```text
서버 실행 → curl로 응답 확인 → ss로 포트 확인
        → (포트 충돌 시) 다른 포트 사용 또는 kill / pkill
        → (외부 접속 안 될 때) 바인딩 주소와 방화벽 확인
```

| `curl URL` | 응답 본문 확인 |
| `curl -I URL` | 응답 헤더 확인 |
| `curl -s URL` | 진행 표시 없이 요청 |
| `curl -o 파일명 URL` | 응답을 파일로 저장 |

| `kill PID` | PID로 프로세스 종료 요청 |

| `명령어 &` | 백그라운드 실행 |

## 6. 시험 대비 체크리스트

### 핵심 개념

- [ ] IP 주소(컴퓨터)와 포트 번호(서비스)의 역할 차이
- [ ] 공인 IP · 사설 IP · NAT 구분, 사설 IP 대역 3가지
- [ ] 주요 포트 번호: 22 · 80 · 443 · 3306 · 6379 · 5000 · 8080
- [ ] `docker run -p 호스트포트:컨테이너포트` 순서
- [ ] TCP(연결 지향·신뢰성)와 UDP(비연결·속도) 비교
- [ ] TCP/IP 4계층과 각 계층의 프로토콜
- [ ] `localhost` · `127.0.0.1` · `0.0.0.0`의 차이
- [ ] DNS = 도메인 이름 → IP 주소 변환
- [ ] ping 실패 ≠ 서버 다운 (ICMP 차단 가능)
- [ ] HTTP 상태 코드 200 · 400 · 404 · 500 · 503, 2xx/4xx/5xx 분류
- [ ] LISTEN의 의미
- [ ] `Address already in use`의 원인과 해결 방법 2가지
- [ ] LISTEN 상태와 방화벽 허용은 **별개**

### 명령어

- [ ] `ip addr`, `hostname -I`, `curl ifconfig.me`
- [ ] `ping -c 4` 의 `-c`
- [ ] `dig` / `dig +short` / `nslookup` / `cat /etc/hosts`
- [ ] `curl` / `curl -I` / `curl -s` / `curl -o`
- [ ] `jq '.name'` / `jq '.users[0].name'` / `jq -r`
- [ ] `ss -tlnp` 옵션 4개 (`-t` `-l` `-n` `-p`)
- [ ] `python3 -m http.server 8080` 구조 (`-m`, 포트)
- [ ] `--bind 0.0.0.0`
- [ ] `kill PID`(기본 SIGTERM)와 `pkill -f 패턴`의 차이
- [ ] `&` 백그라운드 실행

> 명령어를 통째로 외우기보다 **옵션의 역할**을 이해하고, 직접 실행해서 결과와 오류 메시지를 읽어보며
> **서버 실행 → 응답 확인 → 포트 확인 → 프로세스 종료**를 하나의 흐름으로 익히기.
